此前板上已经验证 Web 控制三路舵机、电机串口、GPS 数据、摄像头拍照。匹配位流加入 BOOT 后，做过两次 SSH 重启与 MMIO 写入测试。这里记录的是已有实验结果，不算作本次重新测试。

本次执行代码/配置检查、14 项离线测试、6 个 ARM64 工具交叉编译、AIC 两模块重编译、BOOT 打包和现有完整 rootfs 归档检查；不自动驱动当前电机/舵机、不重刷 SD、不重启板子。模块 vermagic 为 `6.1.111-rt42 SMP preempt mod_unload aarch64`。详细成功/失败项以机器报告为准。

测试兼容虚拟机的 Python 3.6 和本机 Python 3.13。配置脚本仅在临时模拟 SDK 中测试，不覆盖已部署的 SDK 配置。SD 安装脚本通过语法检查，但本次未执行实际写卡。

全新 SDK 完整构建、重生成 TD 位流/FSBL、SD 冷启动、真实机械动作以及公开源码授权范围仍需复核。不能宣称这些已由静态检查保证。

## 已知限制

- WiFi 原厂驱动曾出现 `cfg80211_rx_unexpected_4addr_frame` 告警；并未因归档而修复。
- GPS 程序尚未校验 NMEA checksum；有数据不代表已定位；尚无 FPGA UART GPS 的实现。
- 电机无通信超时自动刹停；Web 无身份验证，仅适合受信实验网络。
- MMIO 状态来自配置，不是硬件 ID 探测；错误位流/地址可能引发不可捕获的 SError。
- 内核名带 `-rt42`，但保存配置未启用 `CONFIG_PREEMPT_RT`。
- USB 枚举次序可能变化；上板后核对 MOTOR/GPS 设备，不能盲目套用 USB0/USB1。
- 历史 FD 自动生成文件含工具路径提示；新机器必须使用匹配官方 SDK/IP，重新导出平台，而不是复制旧缓存。
