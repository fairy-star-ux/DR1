# 复现与构建

## 1. 准备输入

本仓库保存项目源码和配置增量，不包含完整 SDK/商业工具。需要：

| 输入 | 要求 |
|---|---|
| 官方板卡资料/SDK | `uisrc-lab-anlogic`，Buildroot 2022.02.6、Linux 6.1.111 源树，`localversion-rt=-rt42` |
| TD/FD | 优先使用原工程的 TD 2026.1 SP2 和相配 FD；需有效工具授权 |
| 交叉工具链 | SDK `tools/aarch64-linux`，Linaro GCC 7.5.0；裸机 FSBL 使用 FD 自带工具链 |
| U-Boot/Bootgen | 同一官方 SDK 的 U-Boot、`tools/bootgen/linux64/bin/albg` |
| WiFi 固件 | 官方 AIC8800D80，至少含 `fw_patch_table_8800d80_u02.bin` 等完整同套文件 |
| 主机 | Linux 开发机/虚拟机；原验证使用 Ubuntu，16 vCPU；预留 SDK 编译所需空间和内存 |
| SD | FAT 启动分区 + ext4 根分区，Linux root 指向 `/dev/mmcblk0p2` |

主机工具需有 `make`、Python 3、`gcc`、`bc`、`bison`、`flex`、`libssl` 开发包、`u-boot-tools`、`lz4`、`kmod`、`dtc` 和官方 SDK 其余构建依赖。
当前仓库不宣称不同版本 SDK 可以无修改替换。来源与构建产物的 SHA-256 见 `manifests/`。

## 2. FPGA：TD → 硬件平台 → FD/FSBL

1. 将仓库放在无空格/中文的短路径。打开 `fpga/td/fpga_prj.al`。
2. 确认器件 DR1M90GEG400-2、顶层 `system_top`，不是历史 `boat_top` 独立工程。
3. 检查源码及两个 IP：`uisrc/01_rtl/system/system.xml` 和 `al_ip/PLLF9F0D0P0_0/PLLF9F0D0P0_0.xml`。
4. `system` 中 PS Master GP0 已开启并导出；`master_gp0_axi_aclk` 接 `p2f_clk0`，寄存器连接在顶层 RTL。
5. 某些 IPXACT 文件保留原 TD 安装路径提示；若本机不同，在 Design Integrator 配置当前 TD IP depot。不要把安装目录当成项目源码路径。
6. 确认 `servo_control_gp0_axi` 实例 `SELF_TEST=0`、`BASE_ADDR=0x80010000`。核对 ADC 管脚与 SDC 时钟。
7. 运行综合、布局布线、时序检查和 Generate Bitstream。检查 DRC、Setup/Hold 后保存报告。
8. Export Hardware Platform，包含 bitstream；在相配 FD 中导入新 HPF，重新生成/更新平台 BSP 和 FSBL。
9. 仓库 `fpga/fd/soc_base/platform/Design.xml`、`soc_plat.tcl` 和 `soc_fsbl` 保存了当时配置/源文件。旧 `.project/.cproject` 可能含 IDE 路径提示，建议在新 FD 工作区导入并更新平台，不复用缓存/旧 build。
10. 编译 FSBL，得到 `soc_fsbl.elf`；确认导出的 bit 与刚编译的 TD 结果相同（`sha256sum`/`Get-FileHash`）。将本次 bit 和 ELF 放进本地 `artifacts/inputs/`。

重新生成的 bit 可能带时间戳，不要求哈希永远等于历史产物；哈希用来追踪一套输入，不代替时序与硬件验证。
不要手改生成的 PS 底层 wrapper 来“开启” AXI，改 PS GUI/Design Integrator 并重新生成。

## 3. 准备私有配置

Linux 以下命令从仓库根目录运行。设置环境路径示例：

```bash
export SDK="$HOME/uisrc-lab-anlogic"
export REPO="$HOME/rescue-boat-dr1m"
cd "$REPO"
mkdir -p secrets artifacts/inputs
chmod 700 secrets
cp linux/buildroot/rootfs_overlay/etc/wpa_supplicant.conf.example secrets/wpa_supplicant.conf
# 编辑 secrets/wpa_supplicant.conf，填写自己的 SSID/密码。
# 用编辑器创建 secrets/root-password.txt，保存一行非空 root 密码。
chmod 600 secrets/*
```

WiFi 派生 PSK 同样是凭据，不能因为不是明文密码就提交。仓库没有保存原部署网络信息。
可用 `wpa_passphrase` 生成配置，但应去掉其明文密码注释，并避免把密码写进公开脚本。

## 4. 在官方 SDK 中应用配置

先备份已有 SDK 的 `.config` 与自定义修改；该脚本会替换 SDK 内核和 Buildroot 配置。

```bash
python3 scripts/configure_sdk.py "$SDK" \
  --wifi-config secrets/wpa_supplicant.conf \
  --root-password-file secrets/root-password.txt \
  --enable-fpga-servos
```

仅在准备打包并启动匹配位流时使用最后一项；省略则舵机 API 保持禁用。
脚本将 overlay 放到 `$SDK/boards/DR1M/boat-overlay`，向其中复制项目应用与启动脚本，并设置 `BR2_ROOTFS_OVERLAY`。
WiFi/profile 和密码只进入 SDK 本地配置/构建镜像。未配置 WiFi 时可省略 `--wifi-config`，启动脚本会跳过联网。
不用先构建原历史 C 主程序；当前 Web 服务与它相互独立。

## 5. 编译内核、模块、摄像头、rootfs

先准备固件目录，可将官方固件解压到 `artifacts/runtime-deps/lib/firmware/aic8800D80`，或设置 `FIRMWARE_DIR` 指向官方固件所在位置。

```bash
export FIRMWARE_DIR=/absolute/path/to/aic8800D80
mkdir -p artifacts
set -o pipefail
JOBS=16 bash scripts/build_linux.sh "$SDK" 2>&1 | tee artifacts/build-linux.log
```

编译顺序：

1. 同一内核树 `olddefconfig` → `Image modules dtbs`。
2. 内核模块安装到 overlay；从该内核树编译两份 AIC 模块并加入 overlay。
3. 安装完整固件、生成 modules.dep；交叉编译 camera_capture 和诊断工具。
4. 生成 U-Boot 可加载的 `uImage.lz4` 和 `system.dtb`。
5. Buildroot `olddefconfig` → 完整根文件系统，检查最后的 `rootfs.tar.gz` 内容，并以 `--match-repo` 核对 Web 和启动脚本与本次源码一致，拒绝旧缓存版本。

结果在 `artifacts/rebuilt/`，至少包括 `uImage.lz4`、`system.dtb`、`rootfs.tar.gz` 和输入哈希。
不要用 `boards/.../target` 的残留内容代替最终归档检查。`rootfs.tar.gz` 不应只有一个 lib 目录。
`6.1.111-rt42` 后缀来自源树 `localversion-rt`；此配置并未启用 PREEMPT_RT，不应声称硬实时内核已验证。

单独重编拍照程序（不会触碰板子）：

```bash
make -C linux CC="$SDK/tools/aarch64-linux/bin/aarch64-linux-gnu-gcc" \
  BUILD="$REPO/artifacts/tools" -j16
```

## 6. U-Boot 与 BOOT.bin

优先使用同一官方 SDK 已生成并匹配板卡的 `u-boot.bin`。需要从源码重编时，备份并复制 `linux/boot/uboot.config` 到 SDK `sources/u-boot/.config`，复制 `uboot-anlogic-dr1.dts` 到 SDK 同名 Anlogic DTS 目录；按官方 U-Boot 构建流程运行 `olddefconfig` 与 `make`，使用 SDK 的 ARM64 工具链。
U-Boot 的进一步板级依赖仍由官方 SDK 提供，仓库不是其完整源码替代品。

准备本次同套输入后：

```bash
bash scripts/make_boot.sh "$SDK" \
  artifacts/inputs/soc_fsbl.elf \
  artifacts/inputs/system.bit \
  "$SDK/boards/DR1M/buildroot/output/u-boot.bin" \
  artifacts/rebuilt
```

脚本按已验证的官方 BIF 生成 `BOOT.bin` 和 SD ext4 的 `boot.scr`，不改 SD、不写 QSPI。
它与 SDK `create_dr1m_image.sh` 的非 QT/ext4 方式一致，保留 FSBL → PL → U-Boot 的顺序。
不要拿旧 QT 镜像的不同 load/exec 设置随意拼接此 BIF。

## 7. SD 安装与回滚

使用官方 SD 制作工具建立 FAT + ext4 两分区，并确认与硬件启动模式一致；本仓库的安装脚本**不格式化、不分区**。
挂载后用 `lsblk -f` 核对设备身份和容量，不假定永远是 `/dev/sdb`。

```bash
lsblk -f
python3 scripts/verify_rootfs.py artifacts/rebuilt/rootfs.tar.gz
bash scripts/install_sd.sh /media/USER/BOOT /media/USER/rootfs artifacts/rebuilt --install
sync
# 根据实际挂载点卸载两分区，再将 SD 插回板子。
```

安装先备份旧启动分区和 rootfs，检查压缩包，再解包新 rootfs，替换四个启动文件。
旧 rootfs 的多余文件不会自动删除：要求完全干净环境时，先按官方流程创建新分区再安装。
新镜像包含私有网络/账号配置，不要提交 GitHub；照片与已有数据也不要公开。

若无输出或 SError，先恢复备份 `BOOT.bin`、内核/DTB 与匹配 rootfs；关闭 `/etc/default/boat-web` 中的 MMIO 配置后再排查。
不要在不同 BOOT/内核版本间只拷贝 `.ko` 猜测兼容。

## 8. 验证级别

本次整理会运行源码/配置/脚本检查及应用离线单元测试；不自动重编整个 SDK，也不自动更改当前板子。
现有部署曾通过重启与总线写入测试；要宣称全新环境可复现，仍须按《执行测试步骤》完成一次从干净 SDK 到冷启动的完整记录。
