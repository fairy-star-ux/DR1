# 搜救小船系统 —— 执行测试步骤

## 一、环境准备

### 1.1 硬件连接
1. 将飞腾派开发板接通电源（5V/3A）
2. 连接USB转串口线到电机驱动板（识别为/dev/ttyUSB0）
3. 连接GPS模块到UART接口（识别为/dev/ttyAMA2）
4. 连接EC20 4G模块USB线（识别为/dev/ttyUSB2）
5. 连接USB摄像头（识别为/dev/video0）
6. 连接超声波传感器：TRIG→GPIO450，ECHO→GPIO485
7. 连接雷达舵机信号线→GPIO510
8. 连接视觉舵机信号线→GPIO445
9. 连接拨动开关→GPIO446（一端接GPIO，另一端接地）

### 1.2 软件安装
```bash
# 1. 安装Python依赖
sudo pip3 install opencv-python ultralytics psutil numpy

# 2. 下载YOLO模型（如未自动下载）
wget https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8n.pt
sudo mv yolov8n.pt /home/user/

# 3. 确认串口设备存在
ls -la /dev/ttyUSB* /dev/ttyAMA* /dev/video*
```

### 1.3 编译项目
```bash
cd rescue_boat/
make clean
make
# 预期输出：编译成功，生成 boat_main 可执行文件
ls -la boat_main
```

## 二、运行步骤

### 2.1 启动程序
```bash
# 必须以root权限运行（SCHED_FIFO实时调度需要）
sudo ./boat_main
```

### 2.2 启动后操作
```
[初始化] 开关GPIO...
[主控] 进入开关控制主循环

┌────────────────────────────────────────┐
│  系统待机中，请将开关拨到 ON 启动       │
└────────────────────────────────────────┘
```

### 2.3 拨开关ON启动系统
1. 将拨动开关拨到ON位置（GPIO446接地）
2. 系统进入7步启动序列：
   - Step 1: 初始化电机串口
   - Step 2: 初始化超声波GPIO
   - Step 3: 初始化雷达舵机
   - Step 4: 初始化视觉舵机
   - Step 5: 启动vision.py子进程（nice=19）
   - Step 6: 创建6个实时线程
   - Step 7: 系统进入运行状态

### 2.4 系统运行中

## 三、功能测试步骤

### 3.1 电机控制测试
```
测试动作：
1. 观察小船正常前进（电机同速正转）
2. 用手遮挡超声波（模拟障碍物）
3. 观察电机停止 → 视觉舵机转动 → 等待识别
4. 识别"非人"后，观察小船左转/右转1秒 → 恢复前进

预期结果：
- 前进时PWM左右对称
- 停止后PWM归零
- 转向时差速比例约0.6
```

### 3.2 超声波雷达测试
```
测试动作：
1. 在超声波前方放置障碍物（距离<50cm）
2. 观察控制台输出：dist值变化
3. 移开障碍物，观察dist恢复>50cm

预期结果：
- 障碍物距离测量精度±1cm
- 无有效信号时返回999
- 与舵机角度同步
```

### 3.3 视觉识别测试
```
测试动作：
1. 在摄像头视野内放置人形物体
2. 观察result.txt输出：从waiting→processing→yes
3. 检查capture_base64.txt照片生成
4. 检查OneNET平台收到数据

预期结果：
- result.txt正确输出yes
- 照片Base64文件生成
- EC20上报成功
```

### 3.4 GPS定位测试
```
测试动作：
1. 等待GPS模块搜星（ outdoors 约30-60秒）
2. 检查/tmp/gps_data.txt文件内容
3. 调用gps_get_position()获取坐标

预期结果：
- /tmp/gps_data.txt包含有效坐标
- 纬度格式正确（如23.123456）
- 定位状态为A（有效）
```

### 3.5 4G通信测试
```
测试动作：
1. 检查EC20串口AT响应
2. 检查4G网络激活状态
3. 检查MQTT连接状态
4. 手动触发上报（发现目标时自动触发）

预期结果：
- AT返回OK
- +QIACT返回IP地址
- +QMCONN返回0（成功）
- OneNET平台收到JSON数据
```

### 3.6 开关控制测试
```
测试动作：
1. 拨开关ON → 系统启动
2. 系统运行中拨开关OFF → 系统关闭
3. 等待5秒后拨开关ON → 系统再次启动

预期结果：
- ON启动：7步序列完成
- OFF关闭：7步关闭序列完成
- 循环启动：每次都能正常启动
```

## 四、关闭系统

### 4.1 正常关闭
1. 将拨动开关拨到OFF位置
2. 系统执行7步关闭序列：
   - Step 1: 设置退出标志
   - Step 2: 等待电机线程
   - Step 3: 等待传感器线程
   - Step 4: 等待网络线程
   - Step 5: 停止vision.py
   - Step 6: 释放硬件资源
   - Step 7: 重置全局状态

## 五、常见问题排查

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| boat_main编译失败 | 缺少pthread库 | apt-get install libpthread-stubs0-dev |
| 串口打不开 | 权限不足 | sudo chmod 666 /dev/ttyUSB* /dev/ttyAMA* |
| vision.py无法启动 | 缺少Python包 | pip3 install opencv-python ultralytics psutil |
| YOLO模型下载失败 | 网络不通 | 手动下载yolov8n.pt放到指定路径 |
| GPIO导出失败 | 内核不支持 | 检查/sys/class/gpio是否存在 |
| 电机无响应 | 波特率不匹配 | 确认驱动板波特率是否为115200 |
| GPS无数据 | 室内信号弱 | 移动到室外或靠近窗户 |
| 4G无法连接 | 信号弱/APN错误 | 检查CSQ信号强度，确认APN配置 |
